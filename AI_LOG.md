# AI_LOG

Журнал работы с ИИ над тестовым заданием. Записи велись по ходу работы. Ссылки на коммиты ведут к
исправлениям; детали вроде запусков и проверок мутациями взяты из моих записей, в истории коммитов их нет.

## Инструменты и модели

- Claude Code (расширение для VS Code).
- Модели: Claude Opus 5.5, Claude Sonnet 5.5 и Claude Haiku 5.5. Указаны в строках `Co-Authored-By`
  коммитов.

## Ключевые запросы

**1. План по ТЗ.** Попросил составить подробный план реализации тестового задания. Контекст: PDF с ТЗ
целиком. Результат: план с таблицей решений (деньги в `int`, `divmod` для графика, `UNIQUE` на ключ
идемпотентности, атомарный `UPDATE` для статусов), структура проекта и порядок коммитов.

**2. Правила работы.** Попросил описать цикл работы над фичей: ветка, TDD, коммит на каждое изменение,
код-ревью субагентом перед слиянием, PR. Контекст: правила, которые я сам вёл для похожих проектов,
адаптированные под Python и FastAPI. Результат: `CLAUDE.md` и два скилла (коммиты и код-ревью), по которым
дальше велась работа.

**3. Реализация по фичам.** Каждую фичу ставил отдельной командой. Контекст на каждую:
описание фичи, относящиеся к ней правила ТЗ и `CLAUDE.md`. Работали по TDD (сначала падающий тест, потом
минимальный код), после каждой фичи — ревью субагентом, исправления по его замечаниям отдельными
коммитами. Несколько настоящих ошибок нашло ревью, а не тесты, поэтому ревью оставили обязательным шагом.

## Где модель ошиблась и как это заметили

- **Пустой секрет вебхука** (`fe2ead8`). Модель предложила поле `webhook_secret: str | None = None` и пустое
  значение `WEBHOOK_SECRET=` в `.env.example`. Пустая переменная читалась как `""`, и проверка подписи,
  когда её добавят, включилась бы с пустым ключом.
  Заметило ревью. Исправлено: `env_ignore_empty=True` и тест на пустые переменные.
- **Тесты читали `.env` разработчика** (`522e742`). `create_app()` всегда создавал `Settings()`. Заметило ревью;
  проверено запуском `WEBHOOK_SECRET=leaked pytest`: тестовое приложение получило чужой секрет. Исправлено:
  настройки передаются в `create_app(...)` явно, фикстуры создают `Settings(_env_file=None, ...)`.
- **Поле `tariff_id` без строгой проверки** (`38bbb9e`, `53666c5`). `tariff_id: int` принимал `true`, `"1"` и `1.0`,
  а слишком большой id давал бы 500 вместо 422. Заметило ревью. Исправлено: `strict=True`, `gt=0` и верхняя
  граница INTEGER.
- **Тест гонки держался на удаче** (`3c5f214`). В тесте гонки модель опиралась на ссылку на объект в сессии.
  Без неё тест остался бы зелёным, не проверяя нужную ветку. Заметило ревью. Исправлено: шпион за
  `can_transition`, который показывает, что отказ пришёл именно от `UPDATE`. Проверено мутациями.
- **Тест с половиной пустых проверок** (`616ef4f`). Матрица графика рассрочки в половине случаев давала равные
  платежи, где проверка остатка ничего не проверяла. Заметило ревью. Исправлено: добавлены суммы с остатком,
  проверено мутацией.
- **Проверка готовности Postgres по сокету** (`00d498f`). В `docker-compose.yml` модель написала healthcheck
  `pg_isready` без `-h` и, прогнав стек на настоящем Postgres, сочла его достаточным. Заметило ревью: без
  `-h` проверяется unix-сокет, а на пустом томе временный сервер инициализации отвечает на сокете раньше,
  чем база начинает слушать TCP, и API мог стартовать в этом окне и упасть. Модель воспроизвела окно
  опросом внутри контейнера. Исправлено: `pg_isready -h 127.0.0.1`, несколько холодных стартов без падений.
  Вывод: несколько удачных запусков не доказывают, что гонки при старте нет.
- **Задвоенные ограничения в первой миграции** (`9dbd156`). `alembic revision --autogenerate` выдал каждый
  `CHECK` для enum-колонок дважды и сослался на тип из кода приложения без импорта; на Postgres миграция
  упала бы. Заметила сама модель при вычитке черновика, до коммита. Исправлено: `VARCHAR` и один явный
  `CHECK`. Модель также заметила, что `compare_metadata` не сравнивает `CHECK`, и добавила тест, который
  сравнивает их с моделями; что тест ловит потерю ограничения, проверено временной порчей миграции.
- **Миграции из тестов сбрасывали логирование pytest** (`b665a4c`) и **не запускались из другой папки**
  (`6e0460d`). Модель взяла `env.py` и `alembic.ini` почти из шаблона. Заметило ревью: миграции, запущенные
  в процессе pytest, до конца сессии заменяли настройки корневого логгера, а `alembic -c путь/alembic.ini`
  из другой папки не находил пакет `app`. Исправлено: тесты отключают настройку логирования из
  `alembic.ini`, путь к проекту считается от папки `alembic.ini`. Оба случая сначала воспроизведены
  падающими тестами.
- **Удаление данных без спроса.** Проверяя миграции на Postgres, модель выполнила `docker compose down -v`
  и не спросила меня. Команда удалила том с базой, где лежали данные моей ручной проверки (тестовые, но
  восстановить их нельзя). Модель сама сразу об этом сообщила. Дальше для экспериментов она поднимала
  отдельный compose-проект (`docker compose -p <имя>`) и удаляла только его тома. Вывод: удаление томов
  и баз — только после явного согласия.
